# iOS R52 test profile release

R52 is an explicitly activated review profile for `assetVersion=12346`. It is **test-only and incomplete**: the original wire map is not verified, 1,156 reconstructed row IDs are unverified, and field 901 is experimental. The two Downloads shader candidates are not included; `originalshader.unity3d` is present. Keep upstream disabled.

The 878 MB archive is a GitHub Release asset, not a repository file. `config/ios-r52-profile-release.json` pins its tag, asset name, and SHA-256. The workflow verifies the archive and the stager validates all 53 list fixtures and all 3,389 payloads before transfer. Staging uses an atomic directory rename and removes write bits from the staged files and directories. The API container mounts `.local` read-only and verifies profile hashes at startup. Do not edit or replace a staged profile in place; `verify-stage` rejects changed content or writable permissions.

The R52 profile supports only the explicitly requested direct-client host `kick-flight-fenix.us.ci`; other host aliases are not configured or implied. The normal `push` workflow never activates R52. A push containing only the reviewed PR39+R52 path set deploys the API code only and skips Android APK and native R7 snapshot transfer; when R7 is still referenced, deploy preflight verifies the already staged catalog and every payload hash before syncing. The R52 setting remains disabled. A maintainer must upload the exact pinned asset to the `ios-resource-profile-r52` **draft release** and leave it unpublished, then run **Deploy VPS (main)** with `activate_ios_r52_profile=true`. The opt-in uses a separate job with `contents:write` to download the draft and transfers the verified archive directly to the VPS over pinned SSH; it does not create a workflow artifact. The deploy job keeps `contents:read`. This opt-in deploys only the API and checks `/health/ready`, `iosProfile=r52-test`, revision 52, the current-revision protobuf invariants, and one CDN object SHA-256.

Activation builds the API image first, then stops the old revision-47 API, atomically writes the read-only `.ci/ios-wire-floor.json`, and immediately starts the R52 API. If build fails, the floor is untouched and the prior source/API can recover normally. If startup fails after the latch, recovery only reapplies an R52-compatible release and checks readiness; if that fails, it reports operator roll-forward while leaving the old R47 responder stopped. The floor is monotonic: later deployments force R52 on and verify the same profile. Automatic rollback after activation may only use a release with this R52 runtime contract and the same profile hash; it never restores an API that only serves revision 47. Keep the existing native R7 snapshot as a separate immutable profile.

Android remains on `assetVersion=12345` and the existing `/cdn/` routing. The R52 opt-in only selects the iOS `12346` list fixtures and `/ios/cdn/` catalog.
