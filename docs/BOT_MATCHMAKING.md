# Scramble bot composition

Scramble first assigns complete human parties to teams, then fills the open slots with complementary bots and registered decks. The selector runs only for the regular and event Scramble rules (rule IDs 1, 5, 6, and 7). Other matchmaking rules keep their existing roster and deck selection. Gym matches keep the mannequin path.

Human team assignment considers every legal partition of the already selected parties. It first minimizes the difference in human counts between sides, then scores the resulting teams with the same role and archetype coverage rules used for bots. This gives 2/2 for four solo humans and 4/4 for eight solo humans; a three-person party and a solo must stay together, so four humans in that arrangement land 3/1. Party keys are sorted before scoring and team-color swaps are canonicalized, so changing queue arrival order does not bias a unique best partition. Equal-scoring partitions use the battle seed for repeatable tie selection. Interim waiting rosters remain provisional until the match is formed. The existing admission policy still selects the largest set of whole parties that fits 4v4; when the queue order is 3+3+2, the two three-person parties start together and the two-person party stays queued for the next match.

Role coverage comes from the kicker parameter master: Speed (0), Support (1), Attack (2), and Tank (3). The composition favors gaps in each human team's role coverage. It balances repeated roles against coverage, and can reuse a kicker across opposing teams when the available candidates require it. Human account IDs, kicker IDs, costume IDs, and four equipped disc IDs are preserved; human AI parameter and deck IDs remain zero. A seeded selector makes a battle's team assignment and bot roster repeatable while allowing different battles to produce varied eligible picks.

`config/scramble_bot_disc_decks.json` registers 448 eligible kicker/profile deck variants. Each record links a kicker and profile to an existing `masters_kicker_ai_disc_deck` row, its four resolved disc IDs, the kicker's role type, and cast times by disc category. Each kicker/profile pair has four variants. Generate the catalog and its AI deck/disc master rows with:

```sh
python scripts/generate_scramble_bot_disc_decks.py --write
```

The catalog generator validates disc links and effect/category metadata against the served Disc, Skill, and sub-skill masters. Its profile rules reserve useful effects such as healing, team speed, attack buffs, damage reduction, and objective traps, then rank remaining choices by role weights and each kicker's action timings. The timing source is `CAST_CATEGORIES` and `CAST_TIMES` in `scripts/build-action-asset-bundles.py`; these describe action timing by disc category. The generated roster test resolves each selected AI deck through its four AI-disc rows and checks that the resulting disc IDs match the catalog. This verifies that the chosen deck and runtime roster fields stay aligned.

The server source confirms that matchmaking assigns each bot its kicker's existing AI parameter row ID and the selected AI-disc deck ID; Gym keeps its separate mannequin parameter IDs. The catalog and roster changes do not edit AI parameter rows or client AI logic. This establishes which existing AI and deck data the server sends. The partition score uses only configured kicker roles, archetypes, and available bot profiles; it does not model player skill, latency, or live match state. Whether a client AI can coordinate with teammates or execute every high-level role equally well has not been established here; novel team-aware tactics may need client-side logic changes, and this work makes no such behavior claim.
