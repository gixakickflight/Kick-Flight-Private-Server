## 3. Findings worth keeping

- **Account IDs shown as names:** otomo's drafts and schemas store the author's account ID (admin-auth's UUID) in `updated_by` and `created_by`. Its conflict dialogs print that as the name, so a real deployment says "saved by 3f9c2a…". The mock fixtures use emails there, which hides it. Design 18's CFG-G1 and UI-40 fix it.
- **The otomo CLI** (`services/cli`) is a stub that prints "CLI Test". Nothing can push schemas or drafts from a script yet; that needs service accounts (gap G12).
- **Validation fix:** phase A fixed a bug in otomo's local validation, where an error inside a nested table also produced a "False boolean schema" message at the table.
- **KF data oddity:** in `masters_kicker.json`, `voiceActorName` and `cv` disagree, for example Tsubame's "CV: Yuma Uchida" against "Kaito Ishikawa". It's unknown which one the client displays.
- **What `kf.kickers` showed:** loading it into the table editor exposed what phases B and C need. That's design 17 §1.1, in `b36dba9`: references inside one namespace, display names for keys (`1 · Tsubame`), a Table/Records switch, and column widths.

## 6. How to

**Rebuild KF's namespaces and preview them in otomo's admin website** (mock API, nothing persists across a
reload):

```
python scripts/otomo/build_namespaces.py
python scripts/otomo/preview_adminui.py C:\Users\Tanuki\otomo-kf-preview
cd C:\Users\Tanuki\otomo-kf-preview\services\adminui
npm run dev:mock -- --port 5173 --strictPort
```

Open `http://localhost:5173/admin/config/namespaces/kf.kickers` and sign in as `admin@example.com` with any
password.

To reach it over Tailscale, set `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS=desktop-jtr7ml6.tailb9f3d2.ts.net`
before starting the server, then run `tailscale serve --bg "http://[::1]:5173"`. Vite listens on IPv6 only, and
the mock's service worker needs HTTPS, which `tailscale serve` provides.

**Check otomo changes:**

- adminui: `npm run format:check`, `lint`, `typecheck`, `test`, `e2e`;
- Go, in WSL: `PATH=~/go1.27.3/go/bin:$PATH GOTOOLCHAIN=local go test ./...` per module. Two `internal/blob` tests fail on Windows only;
- docs: `~/wikivenv/bin/python services/wiki/build.py docs /tmp/docsite`, which builds in strict mode.

The dashboard golden test fails in the Windows checkout because of CRLF line endings, not code.

**Push to otomo:** from WSL over SSH:

```
git push git@github.com:tanukifurhire/otomo.git <branch>
```

`origin` is HTTPS with a token that lacks the `workflow` scope. Open PRs with `~/.local/bin/gh pr create --base staging`.
